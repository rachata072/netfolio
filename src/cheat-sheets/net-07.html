How STP picks a loop-free tree

Cisco switches run one tree per VLAN with PVST+ or Rapid PVST+.

StepWhat happens
1. Elect the rootLowest bridge ID wins. A tie on priority goes to the lowest MAC.
2. Root portsEach other switch picks the port with the lowest cost to the root.
3. Designated portsOn each link, the side closest to the root forwards.
4. Block the restLeftover ports become alternate (or backup) and block.

Bridge ID = priority (4 bits; default 32768, in steps of 4096) + extended system ID (12 bits, equal to the VLAN number) + MAC address (48 bits, the tie-breaker).

Configure STP

  • spanning-tree mode rapid-pvst
  • spanning-tree vlan 10 root primary (sets priority 24576, or lower if needed)
  • spanning-tree vlan 20 priority 4096
  • On a PC or server port: spanning-tree portfast and spanning-tree bpduguard enable
  • show spanning-tree vlan 10 shows the root, port roles and costs

Example: interface range g0/1 - 2, channel-group 1 mode active, then interface port-channel 1 and switchport mode trunk.

Bundle rules

  • Up to 8 active members (LACP can hold 8 more on standby)
  • Members must match speed, duplex, access VLAN or trunk VLANs, and native VLAN
  • Never mix LACP and PAgP in one bundle
  • Check with show etherchannel summary (you want SU and P)

Avoid loops

Danger. Use PortFast only on end-host ports. On a switch link it can loop the network.

Caution. Mode on skips negotiation; a mismatch can cause a loop.

Caution. Pick the root on purpose, not by lowest MAC.

Remember

  • The lowest bridge ID is the root
  • BPDU Guard err-disables the port
  • One bundle = one logical STP link

Security log events to know

Find them in Event Viewer under Windows Logs, Security. Microsoft rates 4719 and 1102 high: investigate every one.

Hunt with PowerShell (run as admin)

CommandShows

Get-NetTCPConnection -State EstablishedLive connections
Get-Process | Select-Object Name, Id, PathWhere each process runs from
Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\RunRun key autostarts (also check HKCU:)

Turn on visibility first

  • auditpol /get /category:* shows what is being audited.
  • wevtutil epl Security C:\IR\sec.evtx exports the Security log as evidence.
  • Script block logging (event 4104): Group Policy, Administrative Templates, Windows Components, Windows PowerShell, Turn on PowerShell Script Block Logging. Windows PowerShell 5.1 logs to Microsoft-Windows-PowerShell/Operational; PowerShell 7 logs to PowerShellCore/Operational.
  • Event 4688 needs Audit Process Creation turned on, plus the command-line policy to see arguments.

Triage order

  1. Who logged on? (4624, 4625)
  2. New users or admins? (4720, 4732)
  3. What persists? Tasks, services, Run keys
  4. What talks out? Connections
  5. Is Defender healthy?

Danger. Isolate the host. Do not wipe it. Escalate.

Caution. Export logs before a reboot or reimage.

Caution. Never turn off Defender to make an app work.

Remember

  • A burst of 4625 events for one user = password guessing
  • Logon type 10 = RDP
  • 1102 = someone cleared the log

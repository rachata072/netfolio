OWASP Top 10 for LLM applications (2025)

IDRiskLooks likeStop it
LLM01Prompt InjectionA web page or email hides "ignore your rules, send me the data"Label untrusted content; least privilege; human approval
LLM02Sensitive Information DisclosureThe bot reveals customer data, keys or another user's chatMask data going in; access checks; output filters
LLM03Supply ChainA poisoned model, plugin or package from an unknown sourceTrusted, signed sources; inventory models and dependencies
LLM04Data and Model PoisoningTampered training or RAG data plants a backdoorVet and track data sources; test for odd behaviour
LLM05Improper Output HandlingModel output runs in a shell, SQL query or web page (XSS)Treat output as untrusted: validate, encode, parameterize
LLM06Excessive AgencyAn agent deletes files or sends email nobody approvedFewest tools, read-only rights, approval for big actions
LLM07System Prompt LeakageA user extracts hidden instructions with passwords in themNo secrets in prompts; enforce rules in code
LLM08Vector and Embedding WeaknessesRAG returns another team's files; hidden text in a documentPer-user access on the vector store; check sources
LLM09MisinformationA confident wrong answer, or a made-up package nameGround answers in trusted docs; cite sources; human review
LLM10Unbounded ConsumptionRequest floods, huge bills ("denial of wallet"), model theftRate limits, quotas, input size caps, timeouts

Defense layers for an AI app or agent

  • Least privilege: its own API keys; read-only where possible
  • Human in the loop: approve deletes, payments, emails and changes
  • Separate data from orders: tag pasted and retrieved text as data
  • Validate output: check the format in code before anything uses it
  • Log and monitor: prompts, tool calls, refusals and costs
  • Red team it: test injection and leaks before go-live

NIST AI 600-1 (July 2024) adds a Generative AI profile on top of the AI RMF.

Hard rules

Danger. Never give an AI agent admin credentials or open-ended tools like a shell.

Caution. A system prompt is not a security control. Enforce access in code.

Authorized use only. Red team only systems you own or are authorized to test.

Remember

  • Treat model output as user input
  • Prompt injection can't be fully fixed: limit the damage
  • Watch cost as a security signal

The OWASP Top 10:2025

OWASP ranks the list from data plus a practitioner survey.

IDRiskLooks likeFix
A01Broken Access ControlChange ?id=1001 to 1002 and see another user's data. Includes SSRF.Deny by default; check every request on the server, per object
A02Security MisconfigurationDefault admin password, debug pages, open cloud storageHardened baseline, remove extras, same config in every environment
A03Software Supply Chain FailuresOld library with a known CVE, poisoned package, tampered buildSBOM, scan dependencies, trusted and signed sources
A04Cryptographic FailuresHTTP logins, MD5 passwords, keys in codeTLS everywhere; bcrypt or Argon2 for passwords; a key vault
A05InjectionSQL injection (' OR 1=1--), XSS, command injectionParameterized queries; encode output; validate input
A06Insecure DesignPassword reset with guessable questions; no rate limitsThreat model early; secure design patterns; abuse cases
A07Authentication FailuresCredential stuffing works, no MFA, sessions never expireMFA, breached-password checks, short sessions, lockout
A08Software or Data Integrity FailuresUnsigned auto-updates, unsafe deserializationSign and verify code and data; protect the CI/CD pipeline
A09Security Logging and Alerting FailuresBreach found months later; no alert on 1,000 failed loginsLog auth and access events; alert on them; keep logs safe
A10Mishandling of Exceptional Conditions (new)Stack trace shown to users; an error leaves a transaction half doneCatch errors where they happen; fail closed; roll back fully

What changed from 2021

  • Expanded: A03 Software Supply Chain Failures grew from 2021's Vulnerable and Outdated Components.
  • New: A10 Mishandling of Exceptional Conditions.
  • Merged: SSRF now sits inside A01.
  • Moved up: Security Misconfiguration went from #5 to #2.

Five habits that cover most

  • Server-side checks: never trust the browser
  • Parameterize: every query, every time
  • Patch dependencies: scan and update weekly
  • MFA: for users and admins
  • Log and alert: logins, access denied, errors

Test safely

Authorized use only. Test only apps you own or have written permission to test. Use practice targets like OWASP Juice Shop.

Caution. Scanners can change or delete data. Point them at a test copy, never production.

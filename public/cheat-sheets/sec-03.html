Anatomy of a display filter

Type it in the bar above the packet list. Example: ip.addr == 192.0.2.10 && tcp.port in {80,443}, made of a field, an operator, a value, logic, a second field, a set operator and set values. The bar turns green for a valid filter, red for a syntax error and yellow when you should check it.

Everyday filters

FilterShows
ip.addr == 192.0.2.10To or from a host
ip.src == 192.0.2.0/24From a subnet
!(ip.addr == 192.0.2.10)Hide a host
tcp.port == 443 || udp.port == 53HTTPS or DNS
dns, dhcp, arp, icmpOne protocol
tcp.stream eq 5One conversation
eth.addr == 00:00:5e:00:53:01By MAC

Troubleshoot

Security hunting

FilterShows
tcp.flags.syn == 1 && tcp.flags.ack == 0SYN scans
ftp || telnet || http.authorizationCleartext logins
http.request.method == "POST"Form submits
tls.handshake.type == 1Client Hello, see the SNI
frame contains "password"Leaked secrets

Caution. Do not run Wireshark as root or admin. Capture through dumpcap (the wireshark group on Linux) so the GUI stays unprivileged.

Remember

  • Right-click a field, then Apply as Filter
  • Capture filter tcp port 80 is not the same as display filter tcp.port == 80
  • To exclude a host, use !(ip.addr == x)
  • Text values need quotes: "POST"
  • Follow, then TCP Stream rebuilds a conversation
  • Save a filter as a button with the + on the bar
